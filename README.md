# AI Health Records Assistant

**Live: TBD — will be added after Vercel deployment**

Understand your health documents in plain English. Upload or paste a
discharge summary, lab report, or insurance letter and get a plain-English
summary, a follow-up checklist, questions to ask your doctor, and answers
grounded in the document itself — plus a FHIR Bundle viewer.

> **Demo app — do not upload real personal health information. Not medical
> advice.** Summaries are generated by deterministic, rule-based logic
> (not a large language model and not a diagnosis). Data stays in your
> browser (localStorage) unless you export it.

## Features

- **My Records** — list of health documents with type badges (Discharge
  Summary / Lab Report / Insurance Letter / Other), text search, and
  type filter.
- **Add a record** — upload a `.txt` / `.md` file (max 1 MB) or paste text.
  Title (1–120 characters) and document type are validated with Zod.
  Delete with a confirmation step.
- **AI Summary panel** (rule-based) — a 3–5 sentence plain-English summary,
  a Key Findings list, a lab-values table with high/low flags against
  reference ranges, a follow-up checklist (checkboxes persist per document),
  and questions to ask your doctor.
  - Extracts dates, medication names + dosages + frequency, lab values
    with units and high/low flags, diagnoses/conditions, and follow-up
    instructions — only what is literally in the text.
- **Ask a Question** — keyword/retrieval Q&A over the document text.
  Answers quote the exact lines they came from (line citations) and say
  “Not found in this document” when the information is not present.
  Try: “What medications am I taking?”, “What were my lab results?”,
  “When is my follow-up?”
- **FHIR Viewer** (`/fhir`) — paste a FHIR R4 Bundle JSON (Patient,
  Observation, Condition, MedicationRequest, Encounter), validate it with
  Zod, and view a readable, date-sorted timeline plus resource counts.
  A “Load sample FHIR bundle” button provides a valid sample.
- **Export** — download a document’s summary as Markdown, or export all
  records as JSON.
- **Sample data** — three clearly labeled, fictional SAMPLE records are
  seeded on first load: a discharge summary, a lab report, and an
  insurance letter. No real personal health information is included.
- **Privacy** — a prominent disclaimer banner on every page; no accounts,
  no server database, no API keys.

## Tech Stack

- Next.js 16 (App Router, `src/` directory, Turbopack) + TypeScript + Tailwind CSS 4
- React 19, lucide-react icons, Zod validation
- Vitest + Testing Library + jsdom for tests

## How the Rule-Based Summary and Q&A Work

There is no LLM in this app — everything runs offline in `src/lib/`:

- `src/lib/summarize.ts` — deterministic extraction with regular
  expressions and curated lists of common medications, conditions, and
  lab tests. It finds dates, medication names/dosages/frequencies, lab
  values with units, and compares each lab value to the reference range
  printed in the same line (flagging high/low). Diagnoses come from
  “Diagnosis:” labels and a conditions list; follow-ups come from
  sentences containing follow-up / appointment / return / schedule
  language. The plain-English summary is assembled from those extracted
  facts only — nothing is invented.
- `src/lib/qa.ts` — intent detection (medications, labs, follow-up,
  diagnosis, insurance) plus token-overlap retrieval over the document
  lines. Every answer quotes the exact lines it came from, with line
  numbers, and returns “Not found in this document” when nothing
  relevant is present.
- `src/lib/fhir.ts` — Zod schemas for a FHIR R4 Bundle and its
  Patient / Observation / Condition / MedicationRequest / Encounter
  resources, plus a timeline builder that sorts entries by date.

See `architecture.md` and `AI_WORKFLOW.md` for more detail.

## Privacy and Disclaimer

- This is a demonstration application. **Do not upload real personal
  health information.**
- Summaries are rule-based text extraction. They are **not medical
  advice, not a diagnosis, and not a substitute for a clinician**.
- Records are stored only in your browser’s localStorage. Nothing is
  sent to a server. Exporting a file is an explicit action you take.
- Sample records use a fictional patient (“Alex Morgan”) and invented
  values.

## What Would Be Added Next

- A real LLM (with explicit user consent) for richer, more flexible
  summaries and Q&A, with the rule-based extractor kept as a
  verifiable fallback
- Supabase Postgres + Supabase Auth + Row Level Security so records are
  private per user and sync across devices
- HL7/FHIR server integration (SMART on FHIR) to pull records directly
  from a provider, instead of paste/upload only
- PDF upload and OCR for scanned documents
- Medication interaction checks and lab-trend charts over time
- Sharing a record with a clinician or family member (view-only)
